AUDIO FEATURES & MODERATION
================================================================================

8. Audio Buffer Pipeline (400ms Ring Buffer + Profanity Gate)
   Status: CORE INNOVATION - FULLY IMPLEMENTED
   ✓ Microphone audio routed through AudioWorklet with 400ms ring buffer
   ✓ Parallel Web Speech API for real-time speech-to-text
   ✓ Profanity detection against word list with leet-speak regex handling
   ✓ Automatic audio gate closure (500ms mute) when profanity detected
   ✓ Processed audio stream sent to WebRTC peers (not raw mic)
   ✓ Fallback to raw stream if AudioWorklet unavailable (old browsers)
   ✓ Latency target maintained: <600ms (acceptable voice threshold)

   Implementation Files:
   - client/public/profanity-worklet.js (AudioWorklet processor)
   - client/src/audio/AudioPipeline.js (Main orchestrator)
   - client/src/audio/profanityWordList.js (Word list + regex patterns)

9. Speaking Detection
   ✓ Real-time audio analysis for all speakers (local + remote)
   ✓ Volume threshold detection updated every 100ms
   ✓ Visual feedback: blue glow on avatar when speaking
   ✓ Cyan-colored name display for active speakers

10. Profanity Filtering (Non-AI)
    ✓ Keyword-based detection with support for:
       - Standard English profanities
       - Leet-speak variations (e.g., "r3t4rd" → "retard")
       - Spaced-out words (e.g., "r e t a r d")
    ✓ Segment-based muting (not full-stream suppression)
    ✓ Client-side processing (no data sent to server)

WARNING & KICK SYSTEMS
================================================================================

11. Warning System (3 Warnings → Auto-Kick)
    Status: FULLY IMPLEMENTED
    ✓ Server tracks warning count per socket session
    ✓ When profanity detected, client emits profanity-warning event
    ✓ Rate-limiting (2-second minimum between warnings to prevent spam)
    ✓ Warning count displayed to user: "Warning 2/3 — Watch your language!"
    ✓ At 3 warnings → automatic kick + IP ban from room
    ✓ Toast notification shows reason for kick

    Implementation:
    - socketWarnings Map tracks: { count, lastTimestamp }
    - Server-side events: profanity-warning, warning-issued
    - Client-side events: warning toast display, kick handler with message

12. Host Kick System
    ✓ Host can directly kick any participant
    ✓ Kicked user receives professional kick notification message
    ✓ Toast banner displays: "You have been removed from this room"
    ✓ IP ban applied to prevent immediate rejoin
    ✓ 3-second toast display before redirect to home
    ✓ Server removes kicked user from room participant list

13. Vote-Kick System (70% Threshold)
    Status: FULLY IMPLEMENTED
    ✓ Any user can initiate a vote to kick another participant
    ✓ Vote only available when 3+ participants in room (fairness)
    ✓ Server broadcasts vote to all participants (except target)
    ✓ Users cast Remove/Keep votes
    ✓ 70% threshold for successful kick (prevents abuse)
    ✓ 30-second timeout for vote (if not reached → vote fails)
    ✓ One active vote per room at a time
    ✓ Progress bar showing vote progress and countdown timer
    ✓ Visual UI with Remove/Keep buttons for participants
    ✓ Successful vote results in kick + IP ban

    Implementation:
    - activeVotes Map: { roomId → { target, votes: Set, timeout } }
    - Server events: vote-kick-start, vote-kick-cast, vote-kick-active, 
                     vote-kick-update, vote-kick-ended
    - Client UI: Vote banner with timer and vote buttons

14. Kick Notification System
    ✓ Professional kick messages displayed as toast notifications
    ✓ Shows reason: "Kicked by Host" or "Removed by vote"
    ✓ 3-second display duration before redirect
    ✓ Prevents confusion with automatic redirection
