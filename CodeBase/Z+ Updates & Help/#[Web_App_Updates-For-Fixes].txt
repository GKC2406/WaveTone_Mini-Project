Your profanity detection logic is present and should, in theory, mute words like "retard" (which is in your BLOCKED_WORDS list). However, possible reasons you are still able to say bad words include:

Speech Recognition Limitations: The browser's speech recognition may not always transcribe words accurately, especially for slang, accents, or fast speech. If "retard" is not transcribed as expected, it won't be detected.

Profanity Regex: Your regex is robust (handles leet and spacing), but if the speech recognition outputs a word with a typo or unexpected character, it may not match.

Mute Timing: The mute is triggered after the word is recognized, so a small portion of the word may still be heard before the mute kicks in due to processing delay.

Audio Worklet: The worklet only mutes after receiving a message from the main thread. If the detection or message is delayed, some audio may pass through.

Testing Method: If you are testing by speaking and not typing, browser speech recognition may not always catch the word as intended.

Suggestions:

Check the browser console for logs like "Profanity detected" to see if detection is happening.
Try typing the word in a test transcript to see if containsProfanity works as expected.
Add more logging to see what transcript is being checked.
Consider muting audio slightly before the detected word if possible, or increasing the mute duration.

1> Audio Buffer Pipeline (400ms Ring Buffer + Profanity Gate)
   Status: IMPLEMENTED — Core innovation of WaveTone

   What it does:
   > Mic audio passes through an AudioWorklet with a 400ms ring buffer
   > Web Speech API runs in parallel, converting speech to text in real-time
   > Text is checked against profanity word list
   > If profane → worklet gate closes → segment is muted/silenced for 500ms
   > If clean → audio passes through to WebRTC peers

   Architecture:
   Mic → AudioContext → AudioWorkletNode (400ms buffer, gate control)
        → MediaStreamAudioDestinationNode → processedStream → WebRTC

   Mic → SpeechRecognition (parallel, interimResults: true)
        → onresult → check profanity → if detected → postMessage to worklet → gate closes

   Files created:
   > client/public/profanity-worklet.js — AudioWorklet processor (400ms ring buffer + gate)
   > client/src/audio/AudioPipeline.js — Orchestrator (AudioContext + SpeechRecognition + worklet wiring)
   > client/src/audio/profanityWordList.js — Client-side word list + leet-speak regex

   Files modified:
   > client/src/pages/VoiceRoom.jsx — processedStream replaces raw stream in WebRTC addTrack
   > server/index.js — profanity-warning event handler + socketWarnings Map
