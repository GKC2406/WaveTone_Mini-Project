================================================================================
                    FIX SUMMARY: Participant List & Alias Issues
================================================================================
Date: April 9, 2026
Issue: When creating room from browser 1 and joining from browser 2, participants 
showed as "Anonymous, Anonymous" instead of proper aliases like "Host" and actual 
names.

================================================================================
ROOT CAUSE ANALYSIS
================================================================================

1. INCONSISTENT DATA FORMAT
   - Server was sending room-users events in TWO different formats:
     a) Array format: [{ socketId, alias, ... }]
     b) Object format: { roomId, participants: [...] }
   - Client expected array format but received object format
   - This caused the previous "participants is not iterable" error

2. NEW JOINER NOT INCLUDED IN INITIAL PARTICIPANT LIST
   - When a user joined a room, the server sent existing participants first
   - Then added the NEW user to the participants array
   - But the new user never got updated with their OWN info
   - Result: New joiner saw old participant list WITHOUT themselves

3. ALIAS NOT PROVIDED IN JoinRoom
   - JoinRoom page allows users to enter custom alias (optional)
   - If left blank, a random alias is generated
   - However, this wasn't being validated properly on the server

4. MISSING VALIDATION
   - No validation to prevent users from claiming "Host" status
   - Empty aliases not being handled consistently
   - Topic validation missing in CreateRoom

================================================================================
FIXES APPLIED
================================================================================

FIX 1: Standardized room-users event format (server/index.js)
-------
Before:
  - socket.emit('room-users', participants)  // array
  - io.to(roomId).emit('room-users', { roomId, participants: [...] })  // object

After:
  - socket.emit('room-users', participants)  // array
  - io.to(roomId).emit('room-users', participants.map(...))  // array
  
Impact: All room-users events now use consistent ARRAY format

---

FIX 2: Broadcast participant list AFTER adding new user (server/index.js)
-------
Before:
  1. socket.emit('room-users', participants)  // old list only
  2. participants.push(newUser)
  3. io.to(roomId).emit('room-users', ...)  // broadcast to all

After:
  1. socket.emit('room-users', participants)  // old list to joiner only
  2. participants.push(newUser)
  3. io.to(roomId).emit('room-users', participants)  // includes new user!

Impact: All users (including new joiner) now see complete participant list

---

FIX 3: Server-side alias validation (server/index.js)
-------
Added:
  - Prevent "Host" claims by non-first participants
  - Convert empty/whitespace aliases to "Anonymous"
  - Consistent profanity filtering on all aliases

Impact: Only the first participant can be Host, no spoofing possible

---

FIX 4: Client-side alias validation (client/src/pages/JoinRoom.jsx)
-------
Added:
  - Prevent users from entering "Host" as their alias
  - Replace with random alias if attempted

Impact: Better UX, silently prevents invalid alias choices

---

FIX 5: Topic validation in CreateRoom (client/src/pages/CreateRoom.jsx)
-------
Added:
  - Validate topic is not empty or whitespace-only
  - Show specific error if topic is missing

Impact: Prevents empty rooms with missing topics

---

FIX 6: Client-side flexible parsing (client/src/pages/VoiceRoom.jsx)
-------
Added:
  - Handle both array and object formats from server
  - Fallback logic: Array → use directly; Object → extract .participants

Impact: Backward compatible with any format changes
